# 照片墙、公开动作与记录首页交接

基于 `integration/ziwei-20261016 @ e58e4d8d61b0120ee0aa658edf60c721b9aff70c`，包含知微的空间背景修正、紧凑语音气泡和渡鸦状态动画。此次修改限定在 `ziwei_web/`。原生接口实现、权限和生产部署仍由知微负责。本 PR 一并包含 PR #31 的背景预设回归与原验证记录。

## 已实现

- 日志首页：最近一篇真实共享日记主卡、四个紧凑入口、工作/日记数量与日期、最近不同日期的最多三张真实照片缩略图。私人入口不显示数量或日期，进入《默记》不发任何记录请求。
- 记忆首页：读取原生 `MEMORY.md` 的 `chars / budget`，显示容量与进度；没有数字时不编造。主入口打开 MEMORY 原文，其他分类保留既有只读语义。保护状态只取后台明确标记，不把整个 MEMORY 推定为受保护。
- 照片墙：横向日期条的数量来自 `/photos/days`，空日显示「—」与补图入口；当天照片两列排列；54 个不裁剪的小缩略图铺满心形，并有淡轮廓。心形取实际列表，数量不足时循环实际缩略图，翻组可继续取分页。
- 单张详情：原图、作者与时间、全部标注、已编辑标记；同日列表采用原生 `same_day`，按时间连续向下阅读。只给自己的标注显示改/删入口；用户可删除照片，最终权限由原生 403 执行。
- 上传：最多十张，最终 raw 字节上限 9,500,000；9.5 MB 到 12 MiB 的图片尝试浏览器压缩，仍超限则明确失败。成功后重新读取照片列表；失败不插入假照片，重试沿用原 UUID。选择的是归档日期，不冒称拍摄时间。
- 动作列表：每个请求只显示一份，默认折叠，按原生 `seq` 排序，显示工具名映射、短预览、耗时和完成状态。更新列表保留正在播放的媒体元素与展开状态。没有完成事件的动作显示未完成；同工具并发且无关联键时不猜配对。

## BFF 与存储

新 `/api/photos`、`/days`、`/{id}`、`/{id}/file`、`/{id}/annotations` 与 `/{id}/annotations/{note_id}` 通过现有 Hermes 客户端代理到同后缀的 `/ziwei/web/photos`。保留登录与写操作 CSRF 校验，不接受客户端 author/owner/身份覆盖；原生 HTTP 路由注入 USER，知微自己的工具使用 ZIWEI。返回原生 403，并不把隐藏按钮当权限实现。

照片字节仅经 BFF 传递，验证图片类型和 `X-Content-Sha256`，响应 `no-store`。原生密钥不进入浏览器。未修改已有聊天附件取件路由、`collectMedia` 或附件同步协议。

Web SQLite 启动时新增 `tool_actions` 表，只存公开工具名、seq、短预览、关联键、时间与状态。`tool.progress` 的 `_thinking`、`reasoning_content`、完整 `args` 不进入动作表、事件持久化或前端。旧记录没有公开动作时保持没有，不用旧状态文案补造历史。此为追加表，回滚旧 Web 代码可忽略该表。

页面离开或锁定时停止照片轮询、取消请求和上传，清除图片与标注 DOM；迟到响应按页面代次丢弃。照片总列表每次取 100 条，通过翻组继续分页；当天列表保护上限 1,000 条，超限明确显示尚未全部载入。

## 接口缺口与未验证项

- 原生日记只有读取接口。「继续写」因此只把原文引用放入聊天草稿，让用户确认发送；不会自动写日记或启动模型。
- 原生记忆没有「我们的事」「归档」两个独立集合，因此保留已有分类，不生成这两项计数或操作。需知微补充明确数据契约后再接。
- 本轮验证使用隔离 Hermes 服务与浏览器模拟数据，不冒称真实原生权限验收或生产验证。原生照片增删、双方标注同步、伪造修改返回 403、逐字节核对与显式 SHA 部署由知微复核。
- Chromium 移动视口截图不是 iPhone/Safari/PWA 真机证据。用户先前已经确认原生侧滑正常；本轮新照片详情的真机侧滑仍待实机查看。
