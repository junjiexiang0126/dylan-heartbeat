# 知微统一记忆：第一阶段要求与部署阻碍

2026-10-09。用户确认继续执行官方 Hermes 路线。此前容器启动 CI 成果保留；本文件是实施约束，不代表记忆功能已通过验收。

## 唯一权威记忆

- 一个官方 Gateway、一个知微 Profile、一个持久化 HERMES_HOME。所有前端连接它；禁止按 Kelivo/网页/微信创建不同长期记忆 Profile。
- 用稳定 Agent 标识和服务端认证用户映射区分人，不把客户端传来的身份字段视为权限证明。聊天 session 可分开，长期记忆身份不随新聊天变化。
- 原生 SOUL、USER/MEMORY、会话历史、原始资料归档、经历/日志与任务状态共同构成有明确归属的权威记录。采用原生存储；必要的薄适配层只解决身份、访问控制和审计，不重写 Agent。
- 缓存、检索索引和上下文摘要必须能从权威记录重建，不能独立成为新的事实来源。身份/事实更新必须有来源和版本；发现矛盾时保留双方来源并待核对，不静默覆盖。
- 模型连接配置与数据分离；更换模型或前端不创建新数据目录。升级必须保留卷并先备份；数据库格式变化要验证迁移与回退。

## 原始资料与受控写入

system_prompt.txt、care_rules.txt、shared_history.txt 必须完整保存。迁移前列出实际来源、文件大小、SHA-256、目标位置、运行时派生文件与回退方式，交用户确认；不得在公共 GitHub 中保存私密原件。
SOUL/短记忆用于运行，不能替代原件。旧数据库、原始文本和测试版预算审计不删除、不覆盖、不核销。

原生 memory.write_approval 已配置，但它本身不能隔离通用文件/终端工具对同目录的修改。
第一阶段必须补齐权限边界，验证普通检索不产生权威内容变更，以及新增、修改、删除的未授权请求被拒绝。
审批、写入、版本与审计由服务端执行，不能只靠模型提示词。不要在完成隔离前宣布统一记忆权限已完成。
若需要额外沙箱资源、主机敏感权限或新付费服务，另行确认；不得为了达到权限目标擅自扩大授权。

## 第一阶段验收

1. 官方 Hermes 隔离部署：健康、鉴权、直接 DeepSeek 调用和 OpenAI 兼容接口。
2. 统一身份和记忆接入；原件清单核对；迁移须先经用户确认。
3. 自动验证跨前端/跨会话读取一致性、只读不修改、受控新增/更新/删除、冲突处理、重启恢复、卷外备份与独立恢复。
4. 模型切换和 Hermes 升级的兼容性检查在隔离数据副本上进行，不改旧生产或原始资料。
5. 最后一次必要的 Kelivo 实际验收。启动 smoke test 不替代上述端到端验收。

原生 Cron 能力保留安装，但每天六次自主活动的具体配置及验收移到第二阶段；第一阶段不自动创建付费运行的周期任务。其后的 Skill/MCP 扩展不改变统一记忆权威来源。
