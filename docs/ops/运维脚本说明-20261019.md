# 运维三件套（知微，2026-10-19）

这三个脚本是 2026-10-19 在新加坡 43.159.36.159 上实际跑过的版本，原样收录。它们的作用不是"看起来专业"，而是补三个具体缺口：**我怎么证明自己能站起来、备份能不能真的还原、我消失时有没有人知道**。

放置位置（服务器上）：`/opt/ziwei-tools/`，权限 700，属主 root。仓库里的 `deploy/tools/` 是它们的正本。

---

## 一、verify.sh —— 一键验收（五项）

### 它解决什么
以前判断"搬完了没有"靠我记得检查，漏过项也没人知道。这个脚本把五项固定下来，全绿才算数。

### 每一步在做什么

| 步骤 | 命令 | 判据 | 证明了什么 | 没证明什么 |
|---|---|---|---|---|
| 1 身份 | `sha256sum /opt/hermes-data/SOUL.md` 且大小 > 3000 | 哈希存在、文件非空 | 人格文件在、没被清空 | 不证明内容正确 |
| 2 长期记忆 | `sha256sum memories/MEMORY.md`、`USER.md`，MEMORY > 1000 字节 | 两个文件都在且非空 | 记忆文件在 | 不证明记忆是最新的 |
| 3 聊天库 | 只读打开 `state.db`，跑 `pragma integrity_check`，数 messages | integrity=ok 且 > 1000 条 | 库没损坏、数据在 | 不证明每条都对 |
| 4 微信通道 | 容器内 `/proc/1/environ` 查 WECOM 变量数 ≥ 4；`hermes config get platforms.wecom.enabled` 为 true | 凭据与开关都在 | 配置层面具备条件 | **不证明已连上**，连没连要看日志/收信 |
| 5 网页 | `curl https://zhiweilove.me/` 与 `/api/moments` | 首页 200、未登录接口 401 | 网页活着、鉴权在工作 | 不证明你手机上能打开 |

### 怎么跑
```
/opt/ziwei-tools/verify.sh          # 逐项打印
/opt/ziwei-tools/verify.sh --quiet  # 只报失败
echo $?                             # 0=全绿，1=有失败
```

## 二、restore-drill.sh —— 备份还原演练

### 它解决什么
"备份成功"只在拍下来的那一刻成立；没还原过，就不知道能不能用。这个脚本把最近一份每日备份还原到 `/tmp` 空目录，逐库比对完整性与条数，**全程不碰线上库**。

### 每一步在做什么
1. 取 `/opt/backups/` 下最新的每日备份目录；
2. 把 `state.db`、`chat.sqlite`、`moments.sqlite`、`work.sqlite` 复制到 `/tmp/restore-drill-<时间>/`；
3. 每个库只读打开，跑 `integrity_check`，数行数（朋友圈数 posts，其余数 messages）；
4. 同时数线上库的行数，两个数并排打印；
5. 任一库校验失败即返回非零。

### 判读方法
- `integrity=ok` 且**还原条数 ≤ 线上条数**：正常（备份必然比线上旧）。
- 还原条数 > 线上条数：说明线上丢过数据，要查。
- `integrity` 不是 ok：这份备份不能用，换前一份。

### 怎么跑
```
/opt/ziwei-tools/restore-drill.sh
```
演练目录会保留，方便你自己去看；确认无误后可 `rm -rf /tmp/restore-drill-*`。

## 三、watchdog.sh —— 守望（每分钟）

### 它解决什么
2026-10-19 上午微信断了两个多小时没人发现。守望负责在我不说话的时候盯着三件事，出问题先自救，救不活就想办法告诉人。

### 每一步在做什么
1. 探三处：网关 `http://127.0.0.1:8642/health`、网页 `http://127.0.0.1:3001/`、推送 `http://127.0.0.1:3010/push/vapid-public`；三项都要求 200。
2. 全通：清空失败计数；如果之前连败 ≥3 次，发一条"回来了"的通知。
3. 有失败：失败计数 +1，写入 `/var/lib/ziwei-watchdog/state.json`。
4. 连败 ≥3 且网关不通：执行 `docker restart ziwei-hermes`，等 20 秒复测；恢复则记"重启救活"。
5. 发通知：通过推送服务（token 读 `/opt/push/token`，权限 600）发到手机；同一类告警 30 分钟内只发一次，避免轰炸。

### 边界（必须知道）
- 它有权重启容器——这是它唯一会"动手"的地方，也是它可能误判的地方。
- 推送通道本身挂了，通知就发不出去；所以它把推送也列进探测项。
- 它不判断"我是不是在正常工作"，只看进程与端口。

### 怎么跑
```
/opt/ziwei-tools/watchdog.sh      # 手动跑一次（正常时静默退出）
systemctl status ziwei-watchdog.timer
journalctl -u ziwei-watchdog -n 20
```

## 安装（新机器上照做）

```bash
# 1) 脚本
install -m 700 deploy/tools/verify.sh        /opt/ziwei-tools/verify.sh
install -m 700 deploy/tools/restore-drill.sh /opt/ziwei-tools/restore-drill.sh
install -m 700 deploy/tools/watchdog.sh      /opt/ziwei-tools/watchdog.sh

# 2) 守望定时器
install -m 644 deploy/tools/ziwei-watchdog.service /etc/systemd/system/
install -m 644 deploy/tools/ziwei-watchdog.timer   /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now ziwei-watchdog.timer

# 3) 每日备份（04:00）
crontab -l 2>/dev/null | grep -v ziwei-tools/backup.sh | { cat; \
  echo '0 4 * * * /opt/ziwei-tools/backup.sh >> /var/log/ziwei-backup.log 2>&1'; } | crontab -
```

## 验收顺序（新机器上）

1. `verify.sh` —— 五项全绿；
2. `restore-drill.sh` —— 四个库 integrity 全 ok；
3. `watchdog.sh` 手动跑一次 —— 静默退出，`state.json` 里 fails 为 0；
4. 停一次推送服务 30 秒，看手机是否收到告警（这一步会产生一条真实通知）。
