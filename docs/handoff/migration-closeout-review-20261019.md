## 复核发现及修改

- `waiting_front` 和非字典任务校验已经存在于 Work 基线，保留。
- 交接版只判断 `task.get('evidence_waived')`，任意新任务都能设置该字段绕过检查；“只限八条”原先只是任务表现状，不是程序约束。

- 额度从 `evaluate(home)` 对应的 profile 读取，防止进程 HERMES_HOME 与被检查目录不同而读错配置。明确配置必须为 1–48 的整数；损坏、类型错误、超界或读取异常拒绝唤醒，不能悄悄恢复成更大的默认值。
- 返回 `daily_limit`，方便以后区分调度点数量和实际允许次数。计数不因部署或代码修改而重置。
- 增加 `--dry-run` 只读诊断：不写计数、锁或日志，输出 would_wake，不输出任务正文。wakeAgent 固定为 false，防止把诊断模式挂到 cron 后绕过计数授权。该模式只观察条件，不证明实际活动成功。
- 升级控制器的新 SHA256 已与本次审核脚本对应；新增一致性检查。保留上一版已审核镜像脚本的 hash 为可迁移来源，不接受未知手改文件，也不扩大 Agent 写权限。

### 备份与回滚

交接版存在以下问题：只有 `set -u`；数据库 missing/error 被记下后仍可打印 backup done；未把数据库报告持久保存；对 work.sqlite 假设存在 messages 表；未备份完整脚本、技能、附件和运行覆盖树；回滚说明只停 Hermes 后复制网页库，网页服务仍可能写库；密钥快照后部分 inspect 文件可能重新使用较宽权限。

现在两个 shell 入口统一调用 `deploy/tools/snapshot.py`：

- 四个指定数据库全部必需；SQLite backup API 纳入已提交 WAL，逐库做 integrity_check。失败返回非零，不发布完成目录，也不清理旧备份。
- 复制完整 native/web 持久目录及存在的 runtime 覆盖目录，包括隐藏配置、脚本、技能、自主状态、照片和附件；SQLite 陈旧 WAL/SHM/journal 不随库一起恢复。
- 保存两个受保护环境文件和容器 inspect。备份目录在写入前设 700，所有普通文件 600；清单保存大小、SHA256、原模式与 UID/GID，不将密钥打印到终端。
- 新备份经文件哈希、数据库完整性校验并同步写盘后才发布为完成。
- 只清理工具自身识别的七天前完整 daily 备份。prechange、未知旧目录及失败目录不自动删除；失败时不运行保留期清理。
- restore 只能写入新的空暂存目录，拒绝当前数据目录及其父/子目录、备份本身及非空目录。先校验再写入，按清单恢复权限；不自动还原真实数据卷或重启容器。
- 回滚说明要求同时停止 Web 和 Hermes 的所有写入者，保留原现场，先在新目录验证，再显式切换挂载，避免“docker start 仍挂旧目录”的误操作。

**一致性边界：**在线备份只保证每个 SQLite 库各自的一致快照，四库与普通文件没有跨库全局事务保证。
需要迁移时的全局静止点，应先由部署流程暂停全部写入者，再执行快照；本工具不会擅自停服务。
inspect 只记录镜像 ID/参数，不包含镜像字节；跨机器恢复前还要确认对应镜像可获取，不能把数据备份称为完整机器镜像。
