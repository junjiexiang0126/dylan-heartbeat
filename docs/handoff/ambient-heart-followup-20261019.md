# 全站底光与贴纸加载跟进（2026-10-19）

基于 main c84827b；不部署、不修改长期记忆或任何持久化数据。

用户提供 iPhone 浏览器截图：日志私人入口与记忆主卡爱心显示破图，状态栏区域奶白色，与页面彩色底光不连续；要求所有页面统一使用现有底光。

## 证据与边界

- 实际线上四张 PNG 全部 GET 200、image/png。爱心长度 1,599,980、SHA256 6796ba36c5e76b79606a44eef42e6131e891559efc36d51feb83cb14b1aebf34，与仓库相同。四张 PNG 的 CRC 和 Pillow verify 均通过。没有证据说明爱心缺文件或已经损坏；无法仅凭截图判定当时是网络失败还是设备解码失败。
- 旧底光通过 body:has(#logs...) / body:has(#memory...) 启用，其他四页不共用；html 根画布只有 --bg 纯色，ambient 还从 safe-area-inset-top 以下开始。截图顶部颜色断层与这些绘制层差异相符；不是内容 margin-top 能单独解决的问题。
- iPhone 截图是浏览器模式。apple-mobile-web-app-status-bar-style 主要针对主屏 Web App，不能将修改此标签当成浏览器模式白边的已验证修复。

## 修改

- 六页共用原来四组光色、强度、渐变位置和漂移动画；未改变用户认可的日志/记忆背景颜色。
- 根画布也绘制同一组底光，补齐 safe area / overscroll 的背景；正文仍是既有底色加原动画层，避免双重叠光。ambient 从顶部铺满，内容安全区间距保持原样。
- 自选全站壁纸或聊天壁纸时不叠加底光，继续尊重用户壁纸。
- 四张原 PNG 不改像素、不换画。贴纸一次网络失败后仅重试一次（sticker_retry=1），加载前及最终失败隐藏装饰，不暴露破图图标。没有无限重试，也不会用其他贴纸冒充爱心。
- 专项覆盖六页实际完整 HTTP 应用与样式、根画布、安全区布局、壁纸优先、爱心首次失败恢复和永久失败隐藏。API 使用隔离数据，不能视为真实业务调用验收。

## 验收层级

iPhone：尚待部署后用户验证浏览器状态栏、滚动/回弹、PWA；Linux WebKit 不能证明原生 Safari 工具栏消除白边。没有声称真机问题已经完全解决。
