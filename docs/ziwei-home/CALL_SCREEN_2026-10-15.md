# 头像语音通话界面（2026-10-15）

本次只提交前端修改，不部署、不合并到部署源分支。代码位于 `fix/chat-call-avatar-wave`，基于 `fix/web-mobile-ui-overhaul` 的 `e82cabc`。这是聊天页右上角电话按钮打开的通话界面。

## 可验收行为

- 全屏通话页，中央显示已保存的知微头像与昵称；未设置头像时显示昵称首字。
- 声波与头像外圈直接读取 Web Audio AnalyserNode 的音量/频谱：听你说话时读取麦克风，播放回复时读取实际音频，等待回复与静音时归零。没有随机声波或模拟说话动画。
- 接通麦克风后计时；有静音、取消静音、挂断及播放受浏览器限制时的显式播放按钮。
- 静音会禁用麦克风轨道并丢弃当前尚未提交的半句录音；不会把那半句自动发送。取消静音后重新开始收音。
- 挂断、退出聊天或页面进入后台会停止麦克风、录音、播放、声波、计时器并关闭音频上下文。再次通话使用新的 audio 元素，避免跨 AudioContext 重用导致浏览器 InvalidStateError。
- 通话背景跟随现有主题；只对控制按钮使用玻璃效果。未更改底部五个标签、主站 theme-color、后端、Hermes 或数据库。

## 验证与限制

- `npm run check` 通过。
- 最终 Chromium 回归 **27/27 通过**（通话 6 项、资料/字体 2 项，以及聊天最小可用、输入区、审批/图片等回归）；头像资料用例另外连续运行三轮通过。
- 浏览器使用本地隔离后端与测试 Hermes；录音来自浏览器实际振荡器/MediaRecorder，回复是可播放的 PCM 音频。声波测试验证了音量存在、归零、静音及实际播放时间推进，不代表向线上知微发过测试消息。
- 检查 320×568、390×844、844×390 的亮/暗主题布局；实际 iPhone/Safari 麦克风与自动播放行为仍需用户部署后验收。
- 当前语音传输继续使用按句轮流的链路：录完一句 → 发送 → 等待回复 → 播放 → 继续听。实时的是收音/播放声波；**本次没有接入全双工语音服务，不支持一边播放一边插话打断，也不承诺微信式低延迟。** 界面底部会说明这一点。
