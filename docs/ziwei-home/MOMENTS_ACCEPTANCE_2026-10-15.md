# 朋友圈 Web 实现与验收 — 2026-10-15

## 交付与边界

界面保留“朋友圈”页签，微信式头像、昵称、正文、九宫格、点赞名单和评论区；支持图文/纯图片/纯文字、点赞/取消、评论及针对评论回复、本人评论删除、私人空间双方动态删除，不提供编辑接口。图片查看、切换、保存、失败重试。共用已保存头像昵称与主题。

朋友圈专用 `*-moments` 原生会话被排除出聊天历史导入，避免处理指令与动态混进聊天档案。

原生 `post/reply/like/unlike/delete` 追加事件均有接收逻辑；不从模型最终文字伪造动态。context_note 在进入 Web 存储前丢弃。

## 数据与安全

- 独立 moments.sqlite（WAL/FULL，SQLite 事务与唯一约束）及私有 moments-files/attachments；作用域绑定原生地址/会话/凭据，改变后要求审查迁移。
- 复用现有登录、Origin、CSRF。前端不能伪装知微作者；Hermes 没有 Web 业务库凭据。所有显示内容用 textContent。
- 最多九张，每张保存不超过 5 MB，总图片额度 256 MB。浏览器压缩照片至最长边 1600 px 后上传；GIF 不改动且限 5 MB。图片实际类型以文件签名检查。
- 删除清除正文/关联评论、点赞与待办 payload，保留指纹和墓碑防复活；已删除动态的图片接口不可访问。孤立图片文件仍占存储，未来应增加受控清理，不自动扫描或删除其他数据。
- 动态/评论提交编号幂等，原生回复目标唯一；删除后接收到迟到回复也不再展示。朋友圈没有自动写 Hermes 长期记忆；原生运行历史仍可能保留，强制禁用记忆写入需由原生侧完成。

## 主动处理与费用边界

用户发布/评论时落持久化后台任务，服务器启动恢复、10 秒轮询，原生出站 30 秒同步。GET/打开页面只读，不触发新模型任务。单次模型接收丢失后沿用同一 key/输入；超出 1 小时不盲目重投。每次只处理一条活动 run，排队上限 30，当日最多 12 条新的自动互动（曼谷日界）；这些互动与六次自主唤醒分开。10 分钟未终止则停止主动轮询并显示待核对错误，**没有声称取消原生正在执行的任务**；已有 Hermes 运行预算应继续生效。手动重试同步仅读取原生记录，不重新生成已经结束的回复。

回复展示时间在用户动作时持久化：动态 10–20 分钟、评论 3–8 分钟。原生晚于预定时间才生成则到达后显示。新自主动态即时显示，未设置“按点必发”。

原生接口不存在时保存用户内容并明确提示，原生修好后继续处理；不把404空响应或模型输出当附件/动态成功。单页满100条且未明确声明无下一页时，需要原生分页游标，否则阻止不完整的增量检查点推进并显示错误。
