## 完善的内容

| 项目 | 本轮实现与验收方式 |
|---|---|
| 双方头像、字号、紧凑气泡 | 保留上轮逐条消息的左右头像、12–20 px 字号及随字号缩放的气泡。两个人的头像继续读取已有资料。底部五个按钮、theme-color 与 /game/ 未修改。 |
| 相识日期与天数 | 设置→我们的资料填写确认日期；后端验证有效日期、拒绝未来日期、保护 revision，按 Asia/Bangkok 日历计算含当天的天数。没有代填一个未经确认的日期。 |
| 知微的真实状态 | 新增原生 ziwei_status 工具，由知微选择发布四种状态之一。只读接口返回本人发布的值和时间；30 分钟后标记过期，未发布显示未同步。界面不从连接、模型调用或随机数虚构状态，也不代表验证了主观情绪。首页和名字下方共享同一来源。网络连接状态单独显示。 |
| 命令审批 | 原生 approval.request 进入网页选项卡，可“允许本次”或“拒绝”；通话中也能看到。后台核对当前 Web 请求、原生运行及精确 approval request_id，仅提交原生允许的选项；过期失效、他处处理、重复点击不能扩大批准范围。没有自动批准或永久允许按钮。 |
| 原生音频/图片/文件回传 | 新增按原生运行所有权检查的媒体读取接口，只接受该运行最终回复明确给出的 MEDIA 路径；限制在 workspace/audio_cache、安全扩展名及 20 MB 内，拒绝目录、软链接、隐藏路径和遍历。Web 核对大小、SHA256 后保存为私有附件并关联回复；Range、认证下载继续沿用。暂未同步可手动重试。不是任意文件浏览接口。 |
| 文字回复朗读 | 已完成的文字回复可点“朗读回复”；生成原生可播放音频并缓存，重复点击复用文件。明确是语音合成朗读，没有把旧用户录音冒充知微语音。语音依赖固定为 edge-tts 7.3.1，保留 Xiaoxiao 音色，不修改模型或人格。 |
| 语音通话 | 右上角电话现在是轮流语音交流：语音活动检测→停顿后发送原录音→既有 Whisper/Hermes 请求→播放原生音频或合成朗读→继续听。保留聊天记录和请求状态；没有回音自动重发或无界重试。最多 15 分钟/20 轮，每段最多 30 秒。支持浏览器要求再次点击播放时的提示；结束、离开、锁屏停止采集播放。当前为半双工，不是微信式低延迟全双工或可打断实时语音模型。 |
| 录音发送 | 保留轻点开始/结束，新增按住说话、松开发送前预听、上滑取消。上传失败保留录音；处理失败的已保存用户消息可“重新发送”，先把原音频和文字放回发送区，由用户确认后生成新请求。没有盲目自动重发。 |
| 图片查看与媒体重试 | 图片可全屏、上一张/下一张、缩放、双指缩放/单倍时滑动切换、下载原图、明确关闭。图片和音频读取失败有手动重试；退出清理私有预览。 |
| 原生历史与最新增量 | 只读分页拉取当前 Hermes 可访问会话及 user/assistant 消息，原生 session/message ID 作为稳定来源去重，不写 Hermes 或长期记忆。生产启动和每 60 秒同步，也可搜索工具里手动同步。显示实际会话/消息数量及成功/失败状态，重启保留上次完成信息。原有 ZIP 档案仍保留。无法访问的旧生产卷不在覆盖声明内。 |
| 文档读取 | 新增 PDF 可提取文字及 DOCX/XLSX 的受限文本提取，扩大纯文本读取范围。拒绝 XML 实体及过度解压，限制耗时/输出；部分读取明确告知 Hermes。扫描 PDF 无 OCR，旧 DOC/XLS、ZIP 及其他二进制仍是私有保存/下载；不会用元信息回执冒充完整内容理解。 |

## 代码边界

Web 修改分布在首页资料存储、既有聊天服务/附件存储、原生客户端，以及聊天前端；新增 native_history、document_text、voice_synthesizer 和对应 Python 小工具。聊天扩展与通话分别在 public/chat-extra.js、public/chat-call.js，未引入前端框架或 CDN。

Hermes 侧只在部署对接层新增 web_bridge.py、runtime_launch 的加载钩子和语音依赖兼容更新。调用官方的身份验证、运行所有权与审批接口；未修改 SOUL、身份、长期记忆、模型配置、调度、守护逻辑或已有卷。没有创建新服务、迁移数据库或扩大浏览器的密钥访问范围。Web 仅在已有表中增加档案/附件/元信息，旧版本仍能读取；原有请求 scope 与会话未改变。

## 用户线上验收步骤

1. 打开原 Web 地址，检查双方头像、字体及短消息气泡；设置一次相识日期，刷新检查日期和天数保留。
2. 发送一条文字；录一条语音，试听后发送，刷新再播放。试按住松开和上滑取消。
3. 对一条文字回复点“朗读回复”；如知微主动生成带 MEDIA 的原生语音，检查该消息出现播放器。旧消息没有原生音频时不会凭空补造。
4. 点右上角电话，允许麦克风，说一段后停顿，等待知微语音，再回应；结束后检查系统麦克风指示停止。实际模型繁忙时应显示失败，录音仍在聊天记录里。
5. 打开图片，检查切换、放大、保存、关闭；搜索→历史档案查看同步数量与来源，检查刷新不重复。
6. 让知微按实际情况使用 ziwei_status 更新一次；确认名字下方和首页显示相同值与更新时间。未发布前显示未知；不为验收预填一个状态。
7. 当原生确实提出需要批准的操作时，检查出现“允许本次/拒绝”卡片，并核对原生结果。测试不会故意发起危险命令来制造审批。
8. 实际 iPhone Safari、添加主屏幕后的 PWA、Face ID 和大陆网络须在相应设备/网络完成；桌面测试不替代这些结果。

离线队列、按日期跳转、翻译和 Markdown 按此前要求留到下一轮；新视频上传不继续建设。不同聊天平台各自生成请求 ID 的统一去重仍属于跨入口工作，不能靠相同文本比较代替。心潮系统未在本轮部署。
