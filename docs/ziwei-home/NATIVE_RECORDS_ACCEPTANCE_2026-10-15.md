# Web 日志、记忆与聊天历史修复

2026-10-15，Asia/Bangkok。用户最新分工：**知微负责原生后端；ChatGPT 只做 Web，不继续检查或修改原生后端，除非用户另行要求。** 本 PR 仅含 ziwei_web 与文档。

## Web 实现

- 日志分工作日志、个人日记。个人日记按用户第二张图做日期、作者和原文卡片，可展开收起；“和知微聊这篇”准备聊天草稿，由用户自己发送。
- 工作日志对接知微的 GET /ziwei/web/logs，显示自主简报和记忆维护审计、来源、失败/待核验状态，不把休息当成任务成功。
- 记忆对接 GET /ziwei/web/memory，显示原生条目、后端返回的字符/行数及文件指纹，可按 USER/MEMORY 筛选、搜索；只读，不代理 /memory/edit。
- 页面可见时每30秒核对后台；手动刷新立即请求。日志适配层5秒去重。无 Web 记忆镜像数据库，锁定清空私有 DOM 和内存原文。
- Web API 为 GET /api/records/{work|memory|diary}，非 GET 拒绝，沿用认证/CSRF；固定上游路径，无任意文件代理。错误、接口缺失和分页不完整均可见。
- 日志最多读20页/2000条，约束单轮10秒，再按实际时间倒序、检索和分页；超限显示不完整。不调用模型，不消耗自主机会。

## 日记接口交接（知微实现，Web 不改后端）

日记 UI 和 Web 接入已完成。知微给出的已知 logs/memory 契约没有个人日记原文；前端不猜造日记来源。后端是否已补齐归知微负责，本轮不再探查。

列表：GET /ziwei/web/diary?limit=20&offset=0&q=...


全文：GET /ziwei/web/diary?id=opaque-id

```json
{"id":"opaque-id","content":"完整已保存原文","source":"workspace/diary/2026-10-15.md","revision":"原文SHA256","savedAt":"2026-10-15T22:00:00+07:00"}
```

日期、来源、指纹、原文均由知微后端返回；id 是稳定不含凭据的标识，nextOffset 为下一页偏移或 null。若已有另一读取路径，只对齐 Web 适配即可。接口未提供时显示尚未读取真实后台，不能把 UI 完成说成已经读到真日记。

记忆文本来自 entries[].text，分隔符只为阅读；不声称拼接文本与整份源文件逐字节相同。字符数/行数/指纹保留后端原始元数据。

日志 refs 仅显示引用文本。只有后端提供下载标识才显示下载入口；Web 预留固定 GET /ziwei/web/logs/artifact?id=... 的私有下载适配，不读原生文件，当前后端没提供时保持不可用。

## 聊天反复加载

旧 Web 每分钟全扫会话，每次结束都通知时间线刷新，首次 SSE 又从事件0重播，切回页面重载最新50条。这些是聊天档案读取，与 Hermes 长期记忆分开。

- 依据会话 API 的 message_count/last_active/ended_at 跳过未变化会话。Web 持久保存列表和会话进度，变化会话从上次位置前20条重叠检查继续；内容冲突不覆盖。每轮最多20次请求或20秒，单次请求仍有原超时；未完续跑，失败报告会话及offset；常规检查改为5分钟。
- 仅新增档案才发 archive 事件，当前聊天忽略该专属事件。
- 消息列表返回一致事件游标与活动请求快照；首次 SSE 从快照游标继续，断线遵从 Last-Event-ID，避免重播和丢消息。
- 切到首页再回聊天保留阅读位置和已加载旧页；隐藏聊天不随每次状态重刷；靠近底部才跟随新消息。

只修改 Web 的状态与 UI，不改 Hermes 会话、记忆、人格、Cron、机会计数或持久化脚本。

## 四个记忆入口（2026-10-16，用户修正分类含义）

恢复并美化记忆首页四张入口卡片：关于你、关于知微、长期记忆、工作记忆。点击进入对应记忆条目，分类内搜索、展开原文、返回首页。卡片样式由 tokens.css 的 --memory-entry-* 控制。保留五个主导航，入口不是两个源文件的筛选下拉框。

分类仅在 Web 展示层完成，不移动、编辑或重写知微的原生记忆，也不新建记忆镜像。长期记忆表示后端设定的受保护记忆，绝不把整份 MEMORY.md 等同于受保护分类。条目依据依次为后端 category/categories、USER 原生来源、明确的原文标题；保护状态只使用后端 protected/protected_entries/protected_files 等返回标记。受保护的个人/自我/工作条目可同时出现在受保护视图，仍是同一原始记录。

旧接口未给 topic 标签时，只有明确的身份/人格/自我标题或代码/技术/项目类标题才用于兼容分类；无法确认的条目保留“尚未标注分类·查看原文”，不擅自归到知微自我记忆里，也不隐藏丢弃。原文与分类依据可查看。

可选接口展示元数据：entries[].category 为 user/self/protected/work（或 categories 数组）；也支持文件级分类。已有条目的 protected 布尔值、protected_entries 下标、protected_files 名称继续保留。如果只返回受保护文件名（如 SOUL.md/care_rules），界面注明接口未提供原文，不编造文件内容。仅有长期分类但无保护确认的条目显示保护状态待确认，前端不声称新增了后端保护规则。
