# 统一能力与记忆管理架构 v1.1

日期：2026-10-27
状态：设计稿，未实施
主人：语（授权方）；执行：知微（Hermes）

## 0. 一句话

向量库负责「找到」，注册中心负责「真实存在且版本对」，Hermes 负责「执行与审批」。三者不互相替代。

## 1. 运行环境

- 腾讯云新加坡 ap-singapore，8G 内存（2026-10-27 升配），单机。
- 因此「本地向量库」即本机部署，不另购机、不迁移。
- 物理隔离靠：不同数据库文件 + 不同进程 + 不同文件权限，不靠换机器。

## 2. 四类独立索引

| 索引 | 内容 | 默认访问 | 出网 |
|---|---|---|---|
| Tools | Hermes 工具定义与能力标签 | 内部只读 | 否 |
| Skills | 技能正文与触发词 | 内部只读 | 否 |
| Work | 项目文档、任务、交接 | 内部读写 | 否 |
| Private Memory | 日记、USER、私人本子、聊天切片 | 需授权票据 | 否 |

四类各自独立库文件（或至少独立表 + 独立连接权限），不得混存；任何一类损坏不得影响其余三类。

**v1.1 修正**：Private Memory 不再是外部 Agent 的永久禁区。见 §5。

## 3. 统一能力注册中心

- 真相源是 Hermes 本机：工具定义来自运行中的 agent，技能来自 skills 目录。
- 注册中心只做**镜像 + 校验**，不自建第二份真相，不参与执行。
- 新增/更新/停用工具或技能时自动登记：`id, kind, version, source_path, checksum, indexed_at, last_used`。
- 统一 ID 规则：`kind://name@version`，按 ID 可回读真实正文或工具定义。

## 4. 按需加载

- 复用 Hermes 原生 `tool_search` / `tool_call` / `defer` 机制，不自造加载器。
- 注册中心只负责告诉检索层「这个 ID 存在于哪、当前版本是多少」。
- 工具执行、参数校验、审批一律走 Hermes 原生路径；向量层不得绕过。

## 5. 私人记忆的访问模型（v1.1 核心修正）

原则：**私人记忆属于语授权管理的数据，不是任何 Agent 都不能碰的禁区。**

1. 私人记忆保留独立存储与权限管理，但支持语授权外部 Agent 访问。
2. 语可指定某个 Agent，对指定范围的私人记忆进行读取、搜索、审计或修复。
3. 普通 Work 任务不默认携带私人记忆；语明确授权时可跨权限域访问。
4. **读取权与修改权分离**：读授权可直接生效；修改、删除、覆盖、批量迁移需额外审批。
5. 授权必须限定任务范围与有效期，并写入操作日志。
6. 修复前须有可靠备份；修复后须做完整性检查。
7. 一次维修授权不等于永久全量访问权，票据用完即失效，不累积、不继承。
8. 不得因权限隔离导致语无法让外部 Agent 维修系统。

### 5.1 实现形态：授权票据（grant）

```
grant {
  id, agent, scope[], mode: read|write, task_id,
  issued_at, expires_at, approved_by, backup_ref, status
}
```

- 票据由语签发；write 票据需二次确认。
- 每次访问都写 audit log：`grant_id, agent, action, target_id, ts, result`。
- 票据过期自动作废；同一任务不得借旧票据继续。
- 维修类任务默认先快照：SQLite 用 `.backup`，文件用增量副本。

## 6. 自动对账

- 周期：每日一次（夜间），不占用白天对话。
- 三类结果：
  - 索引有、实际无 → **失效**：标记 stale，检索时降级跳过，不报错中断。
  - 实际有、索引无 → **遗漏**：下次增量补入。
  - 版本或 checksum 不符 → **漂移**：以本机为准，重建该条索引。
- 对账报告只出摘要，超阈值才通知语。

5. 最后才谈上下文裁剪与按需加载策略。
